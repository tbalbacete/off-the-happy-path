- `ShareBox.astro` (props `url`, `title`): a `section` named "Share", in the `after` slot between `ReplyBox` and `PrevNext`, with a 2px ink box and 18px 20px padding like the reply box. The permalink is a mono 14px `p` with `overflow-wrap: anywhere`, and the links are a `ul` of `--pen` links with `--pencil` middots (`aria-hidden`). The post route builds the URL with `canonicalUrl(postHref(post.id), Astro.site)`. `PostLayout`'s print block hides `.share` with the reply box. Screenshots (playwright-core, system Chrome, `astro preview`) of № 002 and № 001 at 1280, 390 and 360: the box sits between REPLY and MORE ENTRIES, `scrollWidth == clientWidth` at every width, 16px gutters on phones. Each middot now follows its link instead.
- COPY LINK button and script in `ShareBox.astro`. The button is `type="button"`, rendered `hidden`, and carries the URL and messages in `data-` attributes; the script un-hides it. A click calls `navigator.clipboard.writeText`. On success the label reads COPIED and an `sr-only` `role="status"` paragraph says "Link copied", and both reset after 2 s (a second click restarts the timer). With no clipboard API, or a rejected promise, the script selects the permalink (`Range` + `Selection`) and announces "Press Ctrl+C or Cmd+C to copy". The button is mono 13px uppercase with a 2px ink border on paper, inverts on hover, and has `min-width` set for the longer label. **Astro inlined the script** as a `<script type="module">` in each post page (no `/_astro/*.js` file): 673 bytes, 392 gzipped. Only the two post pages have a `<script>`.

- Card HTML: `ogCardHtml(post)` in `scripts/lib/og-card.mjs`, with `titleSize`, `stampClass`, `escapeHtml`, `entryLabel` and `cardPostFrom` (frontmatter to card fields, naming the file if one is missing). - `npm run og -- <slug-or-number>` / `--all` (published posts) in `scripts/og-card.mjs`, with the browser part in `scripts/lib/og-render.mjs`. It launches the system Chrome through `playwright-core` (new devDependency) at 1200×630, scale 1. It opens `design/og.html` first so the relative font URLs resolve, sets the card's HTML, waits for `document.fonts.ready`, and fails if any of the three families didn't load. Then it writes `public/og/<slug>.png`. Each written card has an `undo` (restore the previous PNG or delete the new one), and a failure part-way undoes the ones already written. `CHROME_PATH=/nope npm run og -- 2` prints `Chrome not found at /nope. Set CHROME_PATH to a Chrome or Chromium binary.` and exits 1.

The width and height stay 1200×630 and other pages keep `site.og`. `BaseLayout` and `PostLayout` pass it through. `src/lib/og.ts` has `postCardPath(slug)`, `postCardAlt(no, title)` (`№ 002: The time we didn’t save`, title as typed) and `postOgImage(...)`, the build guard. - `npm run publish` makes the card first. `publishPost` takes an injected `card(post)` step that resolves to an undo. The post's frontmatter with the new date and `draft: false` becomes the card's fields (`cardPostFrom`), the card is rendered, and only then is the post written. If the card throws, nothing is written and verify doesn't run. If verify fails or throws, the post is restored and the card's undo runs. The CLI's step is `renderCards` with the system Chrome. Its success message lists both files for `git add`, and a `CardError` (Chrome missing, fonts not loaded) prints one line and exits 1. Tests: `tests/scripts-workflow.test.ts` (the card gets the new date before the file changes, a card failure writes nothing and skips verify, undo on fail/throw but not on pass, a bad card field is refused before rendering) and `tests/scripts-integration.test.ts` (a stub card writes a stand-in file in the temp folder: card failure changes nothing, a failed build removes the card, a publish makes the card with today's date). 262 tests.
